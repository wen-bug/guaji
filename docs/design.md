# 挂机家园 2D 横版原型设计基线

## 产品定位

这是一个运行在 Windows 任务栏上方的 2D 横版在线挂机家园原型。玩家以账号持有历练进度、资源和角色，通过招募组成最多 8 人的角色库并选择最多 4 人出战，再通过种田、炼器、炼丹和自动历练形成成长闭环。

第一版用于验证以下体验：

- 桌宠窗口可以长期置顶运行，但不打断桌面工作。
- 玩家在 5 分钟内获得角色并理解家园入口。
- 家园生产提供可预测资源，历练提供随机资源、经验和稀有装备。
- 角色、装备、建筑和账号历练共同构成长线目标。
- 一小时内可以完整经历一次招募、生产、历练、装备和成长循环。

坊市已作为物品经济闭环实现；农田等生产离线收益、固定主角、手动战斗、命格觉醒和更多内容不属于第一版。

## 运行边界

### 在线挂机

“挂机”指程序在桌面前台或后台持续运行。只有场景树正常处理帧时，以下内容才推进：

- 农田生长。
- 炼器和炼丹任务。
- 持续 Buff 时间。
- 历练刷怪与战斗。

关闭程序、系统休眠或进程暂停期间不累计进度。存档只保存任务已完成的进度，不保存退出时间，也不在下次启动时补算时间。

### 支持平台

第一版支持 Windows 10/11，目标窗口为 `960x480`：

- 无边框、透明、不可缩放并保持置顶。
- 使用当前显示器的可用区域，水平居中并让窗口底边贴近任务栏顶部。
- 在 100%、125%、150% DPI 下保持内容完整可见。
- 切换显示器或任务栏位置后重新进入程序时，应按当前显示器重新定位。

macOS 和 Linux 可以运行 Godot 工程，但不承诺任务栏定位与透明置顶行为。

## 账号与角色模型

- 不存在固定主角，账号是全局进度主体。
- 账号保存独立的历练等级和经验，用于决定敌人、招募候选和掉落等级。
- 所有战斗角色均通过招募获得，角色数据保存在 `companions`；家园生产不绑定角色。
- 出战顺序由 `party_order` 保存，最多 4 人；候补顺序由 `reserve_order` 保存，角色库最多 8 人。角色可以上阵、下阵或永久放生。
- 队伍为空时不能进入历练，但仍可刷新候选人以及使用农田、炼器和炼丹。
- 每名角色独立保存属性、五行、装备、技能、命格、生命、法力、等级和经验。

旧存档中的固定 `player` 数据只用于迁移，不进入当前队伍模型。

## 当前数值闭环

- 当前闭环为“历练清场 -> 逐只掉落与胜利奖励 -> 种植/炼丹/炼器 -> 角色与装备成长 -> 更高阶地图”。不新增任务系统，`task_exp` 只保留兼容。
- 历练等级只影响地图解锁、地图怪物等级和建筑强化上限。建筑上限为 `min(10, 1 + floor((历练等级 - 1) / 5))`；旧档超前建筑不降级，但追平前不能继续升级。
- 招募候选等级等于招募建筑等级（1-10），不读取历练等级。角色每 10 级必须消耗破境丹，根骨不再提供免费突破。
- 完整且有奖励的遭遇胜利才推进 `reward_progress`：每 5 胜获得 1 张功法残页。失败、主动返回和训练战均不推进；装备图纸及其保底已退出当前系统。
- 普通炼器消耗矿石 4；所有已注册装备模板均可用相同成本定向打造，不需要图纸或额外解锁。装备升阶消耗矿石与升阶石，分解返还阶位与强化投入对应的强化石。
- 五张历练地图在 1/6/11/16/21 级开放；每名队员生成 2 个敌人，总数限制 1-8，有放回抽取，逐只结算奖励。

## 核心循环

1. 使用初始灵石招募第一名角色。
2. 使用草药种子开始种田；炼丹建筑 1 级自动开放调息丹。
3. 进入历练，自动遭遇敌人并获得经验、草药、矿石、灵石和低概率装备。
4. 收获草药后立即炼丹；积累矿石后立即炼器。
5. 给角色穿戴获得的装备或使用丹药。
6. 将过剩战利品、作物和丹药在坊市回收或提交委托，换取坊市令购买轮换补给。
7. 使用新增战力继续历练，并用资源提升建筑、招募更多角色。

### 首小时目标

| 时间窗口 | 目标事件 |
| --- | --- |
| 0-5 分钟 | 完成首次招募并开始第一块农田 |
| 5-10 分钟 | 进入历练并完成首次遭遇 |
| 10-20 分钟 | 完成首次农田收获 |
| 20-40 分钟 | 材料足够后立即完成首次炼丹或炼器 |
| 45-60 分钟 | 穿戴装备、提升账号历练等级，并完成至少一次建筑升级 |

随机结果按中位体验满足该窗口；极端随机结果可以提前或延后，但不能造成资源死锁。

## 地图与交互

家园场景为 `res://scripts/map/home.tscn`。原 `meditate` 节点映射为招募，`farmland`、`forge`、`alchemy`、`fight` 分别打开种田、炼器、炼丹和历练面板；坊市通过家园 HUD 菜单进入，不增加建筑等级。

通用交互流程：

1. 点击家园建筑。
2. HUD 打开对应面板并恢复已保存位置。
3. 选择配方、数量、种子或目标操作。
4. `GameState` 校验并立即结算炼丹/炼器，或启动农田生长计时。
5. `GameState.changed` 刷新 HUD，并触发 0.5 秒防抖保存。

角色在家园使用 `IDLE`、`ROAMING`、`TALKING`、`PAUSED` 表现状态；历练时进入跑图和战斗表现状态。

## 资源经济

正式新档只拥有：

- `spirit_stone x1`：完成首次招募。
- `herb x1`：作为首个农田种子。
- 五本初阶技能书各 1 本：招募角色后用于学习雷击术、蚀骨毒雾、回春术、燃锋诀和玄甲术。

炼丹建筑会按等级自动开放配方，新档不再发放调息丹方。

`game/development/seed_test_inventory` 默认为 `false`。只有显式开启时才补齐全部测试物品和基础装备，且该开关不写入存档。

| 资源 | 主要来源 | 主要消耗 |
| --- | --- | --- |
| 草药 | 农田、林狼掉落 | 炼丹、农田与农田升级 |
| 矿石 | 林狼掉落 | 炼器和炼器升级 |
| 灵石 | 林狼低概率掉落 | 招募、招募升级、普通属性强化 |
| 装备 | 炼器、敌人稀有掉落 | 穿戴、强化、替换或丢弃 |
| 丹药 | 炼丹 | 恢复、突破、持续 Buff、永久强化或坊市回收 |
| 坊市令 | 物品回收、一次性委托 | 购买轮换商品、手动刷新 |

资源定义、建筑成本、生产时长和掉落概率以[内容数据表](item-table.md)为准。

### 坊市经济闭环

坊市每 600 秒按现实时间免费刷新 6 个不重复商品和 3 项委托，离线时间有效。手动刷新只更换商品，费用按 2/4/8/16 坊市令递增并在免费刷新后重置。回收必须按完整批次提交，贵重物品要求二次确认；商品售价、回收比和委托奖励由统一数据表校验，禁止购买后直接回收、交委托或通过打造分解获得净增坊市令。

## 成长系统

### 账号历练

胜利时账号获得敌人经验。账号历练升级阈值初始为 40，之后每级增加 20。账号历练等级决定敌人、候选角色和装备的生成等级。

### 角色升级与突破

- 参战角色胜利时各自获得敌人经验。
- 当 `exp >= next_exp` 且等级上限已开放时升级。
- 升级消耗当前 `next_exp`，然后执行 `next_exp = int(next_exp * 1.35) + 20`。
- 每级自动分配 5 点成长；`max_hp` 每点 +4，`max_mp` 每点 +2，其余每点 +1。
- 招募时从十项成长属性中抽取一个主属性和两个不重复副属性。每点按主属性 50%、两个副属性各 15%、完整属性池随机 20%分配。
- 每名角色同时从普通和五行六类中等概率获得一个永久 `combat_affinity`，该标签与五行数值最高项相互独立。
- 达到等级上限时可使用突破丹；若根骨高于当前等级，也可免道具打开下一阶段。

### 属性读取

- `total_stat = 基础属性 + Buff + 装备 + 命格`
- `total_element = 基础五行 + 装备五行 + 命格五行`
- `element_power = 木 + 火 + 土 + 金 + 水`
- `total_attack = 基础攻击 + int(element_power * 0.15) + Buff + 装备 + 命格`
- `total_defense = 基础防御 + Buff + 装备 + 命格`
- 最高五行为总值最高的五行，仅用于数值展示和兼容查询，不作为受击克制标签。

## 家园生产

招募、农田、炼器和炼丹建筑均为 1-10 级。升级成本和等级效果由 `DataTables.BUILDING_DEFS` 及对应查询函数提供。

- 招募：刷新免费，招募消耗灵石；建筑等级提高候选命格数量上限。
- 种田：消耗 1 个作物种子并占用农田格；产量受作物和建筑等级影响，作物继续独立计时。
- 炼器：固定消耗矿石并立即生成装备，装备等级使用账号历练等级。
- 炼丹：只能选择已学丹方，按数量扣除材料并立即生成丹药。
- 程序关闭后农田停在已保存进度，不补算离线时间。
- 账号保存三类生产建筑的永久品质；当前炼器每点品质增加 5% 升阶概率，最高 95%。

生产公式和物品规则见[物品系统](items.md)。

## 历练与战斗

进入历练约 1 秒后触发首场遭遇；胜利后，队伍在透明历练层中等待 3–5 秒再次遇怪。每轮由存活角色按 `party_order` 逐个行动并归位，然后敌人行动。

- 普通攻击依赖形象 Hitbox 与目标 Hurtbox 的真实碰撞。
- 技能与丹药由 AI 自动选择，不提供手动控制。
- 技能在特效有效帧结算，动画播放完毕后才推进当前角色回合。
- 技能和丹药冷却单位为角色自身回合；释放后写入整数回合，百分比修正后向上取整。
- HUD 显示伤害和治疗浮字。
- 普通攻击使用攻击者 `combat_affinity`，技能和 DOT 使用自身 `element`；五行克制提高 25%伤害，被目标反克则降低 25%，普通属性始终为中性。
- 胜利结算账号经验、参战角色经验、战斗熟练度、普通掉落和独立装备掉落。
- 主动返回会放弃当前遭遇，不结算奖励，也不恢复生命和法力。
- 队伍全灭不结算任何奖励或战斗熟练度；全员生命、法力恢复到总上限的 50% 后自动返回家园。

完整流程、效果触发顺序和伤害规则见[历练与战斗](battle-expedition.md)。

## 装备与命格

装备包含武器、头盔、护甲、胫甲、护手和两个饰品槽。装备实例保存阶位、等级、基础属性、随机词条、强化和洗练结果；穿戴时才检查需求。

命格提供角色长期差异，不允许普通洗练。当前实现支持基础属性命格；生产不读取人物命格。主、副、缺陷品质结构与觉醒仍是规划。详见[先天命格](innate-traits.md)。

## HUD 与存档

HUD 提供队伍、背包、招募、种田、炼器、炼丹、历练、返回和调试面板。弹窗可以拖动，位置保存到 `user://save.cfg` 并在恢复时限制在视口内。

存档策略：

- `GameState.changed` 或 HUD 位置变化后 0.5 秒防抖保存。
- 正常退出或关闭窗口时强制保存一次。
- 损坏、无法解析或缺少字段的存档回退到默认值。
- `GameState.schema_version` 负责游戏数据迁移，旧字段按现有迁移规则处理。
- 存档不记录退出时间，不用于离线收益。

## MVP 验收

- 新档没有测试装备、高阶材料或属性作物，但能完成首次招募和种植。
- 队伍为空时仍可生产，历练入口给出明确提示且不会进入无解状态。
- 首小时所有核心资源都有来源和消耗，固定随机种子下不存在资源死锁。
- 胜利奖励只结算一次；全灭不发奖励并自动返回家园。
- 5 回合技能严格按角色自身回合恢复，HUD 使用“回合”文案。
- 炼器只消耗矿石，炼器和炼丹点击后立即进入背包。
- 正常退出不会丢失最后 0.5 秒内的变更，损坏存档不会阻止启动。
- Windows 10/11 在目标 DPI 和多显示器场景下保持透明、置顶且贴近任务栏。

## 维护约定

- `DataTables` 是当前数据事实来源，[内容数据表](item-table.md)是其文档化索引。
- 新增物品或生产规则时同步更新[物品系统](items.md)和[内容数据表](item-table.md)。
- 新增富文本描述效果时同步结构化数据、实际结算规则、渲染器和回归测试，禁止只写展示文本。
- 新增命格时同步更新[先天命格](innate-traits.md)。
- 修改战斗流程、冷却、效果或失败规则时同步更新[历练与战斗](battle-expedition.md)。
- 未实现内容必须显式标注“规划”，不能写入已实现清单。
